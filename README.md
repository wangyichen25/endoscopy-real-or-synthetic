# Endoscopy reader study

The active collection method is **Mayo Microsoft Forms**. GitHub Pages hosts the unchanged 100-image assessment; the final **Continue to Microsoft Forms** button transfers a complete assessment to the owner’s Mayo Form. The reader must select **Submit in Forms** and see its confirmation to finish. Merely opening the form does not prove receipt.

Website: https://wangyichen25.github.io/endoscopy-real-or-synthetic/

Source repository: https://github.com/wangyichen25/endoscopy-real-or-synthetic

**Mayo sign-in is required.** The Forms owner UI confirms that “Anyone can respond” is disabled by the organization. No external/public-respondent access has been claimed or enabled. The form’s response results remain private to the owner; no summary-sharing link was created.

## Active files

- `index.html`, `style.css`, and `app.js`: profile, 100-image review, missing-answer navigation, local draft, JSON backup import/export, and final Forms transfer.
- `protocol.js` and `study.json`: numeric experience, one Yes/No authorship permission, sharing acknowledgment, original image IDs/hashes, and guarded packet validation. The active fingerprint remains `19c2395d995ae632ab6d584bc2a2f142b35f760d4df39b3bde894043d423daec`, preserving existing reader drafts.
- `config.json`: active method, public Forms response URL, and question IDs copied from the Forms UI’s generated prefilled link. These are identifiers, not authentication secrets.
- `forms-transfer.js`: validates all 100 judgments, encodes all 100 answers, the complete study fingerprint, and response UUID into a 204-character code, builds the prefilled link, and parses downloaded blocks for analysis checks. Spaces must use `%20`; the actual Forms UI treated URLSearchParams `+` as literal data. Choice values use the JSON-quoted strings generated by Forms.
- `prepare.py`: reproducible image-bank preparation, checking each image byte against the five original reader exports.
- `sync-server.py`: copies the canonical frontend and active settings into the retained optional server checkout.

The Mayo Form asks for name, numeric experience (0–80 including decimals), the same single Yes/No authorship permission, the transferred judgment block, and the same sharing acknowledgment. Mayo also records authenticated name/email and submission time. Forms completion duration measures only the final submission step, not the 100-image assessment. Individual image decision timestamps remain in the original optional JSON backup. Readers can download/save a receipt through Forms.

## Login URL repair

The original readable 100-line answer block caused AADSTS90015 when Forms embedded the long link in its Microsoft sign-in request. The active `SNEL2` transport uses 204 characters: full study fingerprint, UUID without separators, and exactly 100 R/S/U judgments in B001–B100 order. The test transfer URL is 605 characters. The parser retains support for earlier readable records. The packet fingerprint and browser storage key remain unchanged. Do not revert to long response text in prefilled URLs. A received compact QA record was read back and independently decoded with all 100 judgments matching.

## Score after submission

The Forms custom confirmation message contains a **View your score** return link. Its fragment supplies a scoring key; the website verifies its SHA-256 commitment in `config.json`, removes the fragment from the address bar, and displays aggregate accuracy only. The real scoring key and confirmation URL are held privately in `data/reader-study/score-20261115-v1/`; never copy them into public source, screenshots, logs, or invitations.

The displayed percentage follows the current study definition: correct Real/Synthetic judgments divided by all decisive Real/Synthetic judgments; Unsure is reported separately and excluded from that denominator. All-Unsure responses show no percentage. No image-level answers or correctness are displayed. Score revelation returns a read-only summary, and only aggregate score data is persisted. The scoring key itself is not saved in browser storage.

On transfer to Forms, the website saves a snapshot of exactly the transmitted packet. The confirmation return scores this snapshot even if the local draft was edited later. Earlier participants without a snapshot can use their completed local draft or restore their response backup; their score is labeled as calculated from saved answers. Use the same browser/device for the return link, or restore the complete backup. Existing browser storage keys, study fingerprint, images, and Forms field IDs are unchanged.

This static-site return is **not a cryptographically verified Forms receipt**. Forms remains the authority for actual submission. The confirmation link can be forwarded, and a technical participant can inspect its client-side scoring information. It keeps labels out of public GitHub files and normal pre-submission navigation; it is not server-enforced secrecy. Do not use displayed scores as an authoritative analysis dataset; decode and validate the saved Forms export instead.
